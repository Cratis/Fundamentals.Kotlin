# Fundamentals Kotlin parity map

This is the 0.4.0 compatibility ledger, not a claim of whole-product parity. The two artifacts are `io.cratis:fundamentals` and `io.cratis:fundamentals-jackson`. Kotlin and Java share the same JVM API; Jackson integration is optional.

## Authority

C# [Cratis Fundamentals](https://github.com/Cratis/Fundamentals/tree/f87af60265a2e59bd9b7435b0386ee06cb6d646a) is authoritative, pinned at **`f87af60265a2e59bd9b7435b0386ee06cb6d646a`**. All C# paths in the ledger are relative to `Source/DotNET/Fundamentals` at that revision unless explicitly prefixed `Fundamentals.Specs` (a sibling directory). Built-in Guid, DateOnly and DateTimeOffset JSON forms also depend on System.Text.Json. Hand-derived fixtures are not a live .NET oracle.

Kotlin implementation patterns and repository configuration are seeded from [Arc.Kotlin at 8a4a9be13b4e4a9bb5c20d238726c641fb4412a2](https://github.com/Cratis/Arc.Kotlin/tree/8a4a9be13b4e4a9bb5c20d238726c641fb4412a2). Casing fixtures originate in [Fundamentals.Go at c04690df426c5383b62dbf6c71bd799530d5bf0a](https://github.com/Cratis/Fundamentals.Go/tree/c04690df426c5383b62dbf6c71bd799530d5bf0a). Its older C# pin was checked against this authority: the casing implementation and specification are unchanged. Go-only invalid UTF-8 rows were removed; JVM UTF-16 preserves the original unpaired-surrogate case directly. See [casing provenance](../Source/Fundamentals/src/test/resources/strings/README.md) and [concept fixture provenance](../Source/Jackson/src/test/resources/golden/README.md).

## Concept conversion and exception mapping

Core has no Jackson dependency. Descriptors cache the existing record → public static `of` → public single-argument constructor order. Kotlin factories need `@JvmStatic`; named modules must open the package to reflection. `ConceptAs.valueTypeOf` retains its existing type-discovery behavior.

`ConceptFactoryConversionTest` pins the C# `ConceptFactory`, `ConceptMap` and `TypeConversion.cs` branches: identity, one-level concept unwrapping, canonical UUID strings and .NET's little-endian-first-fields 16-byte UUID representation; exact signed integer widths; numeric/string floating point and `BigDecimal`; boolean text; ISO date/time/offset text; and string targets (`BigDecimal.toPlainString`). `BigDecimal` identity retains scale. Collections and other targets have identity-only support, not general conversion parity. DateTime/LocalDateTime, TimeSpan/Duration and byte-array targets are not converted.

## Generated-value exception mapping

All generated-value errors map to `IllegalArgumentException`, except JVM non-null boundaries (`NullPointerException`). Factories are internal; there are no new public exception classes. The original pattern and parser reason are retained. Enum spellings and timestamp rendering use JVM forms.

| C# exception | JVM result |
| --- | --- |
| `InvalidValuePattern` | `IllegalArgumentException("Invalid value pattern '<pattern>': <reason>")`, including budget failures and invalid support indices |
| `InvalidIntegerRange` | `IllegalArgumentException` identifying both inclusive bounds |
| `InvalidNanoIdSize`, `InvalidNanoIdAlphabet`, `InvalidByteCount`, `InvalidTypeIdPrefix` | `IllegalArgumentException` preserving the respective bounds/alphabet/prefix reason |
| `UnknownChecksum` | `IllegalArgumentException("Checksum '<algorithm>' is not a supported checksum algorithm for this operation.")`; `NONE` is invalid for validation |
| `UnknownValueEncoding` | Undefined numeric enum values cannot be represented on the JVM; no runtime branch. Java null fails at the non-null boundary |
| `EmptyPatternSupport` | `IllegalArgumentException("Value pattern '<pattern>' has no values with an emittable check digit.")` |
| `PatternRequiresGenerationContext` | `IllegalArgumentException("Value pattern '<pattern>' requires a generation context for its UTC date segments.")` |
| `MissingGenerationTime` | `IllegalArgumentException("A generation context must contain the time the operation was received.")` |
| `GenerationTimeBeforeUnixEpoch` | `IllegalArgumentException` identifying the unsupported instant; applied to UUID v7, ULID and TypeID, not date patterns |
| `ArgumentNullException` | Java null arguments fail with `NullPointerException` at Kotlin non-null boundaries |
| JVM-only year range | `GenerationContext` construction rejects UTC years outside 1–9999 with `IllegalArgumentException`; C# cannot construct these values |

Patterns substitute one captured UTC date; the tenant does not affect built-in strategies. Checksum validation ignores printable nondigits in the payload but requires the exact numeric trailing suffix. Pattern membership is an internal shape check and does not imply arithmetic checksum validation. Both public validation entry points reject `Checksum.NONE`.

The applicable pinned vector sections are all exercised: 19 support, 25 invalid-pattern, 10 membership, 18 checksum and 24 validation rows. Screenplay binder assessments and range source parsing are deliberately outside this runtime API. UUID v7/ULID/TypeID timestamps are UTC Unix-epoch milliseconds; sub-millisecond precision is truncated. Captured date patterns can use pre-epoch dates other than the missing-time sentinel.

## Wire and language differences

- **Concept values and null:** Java/Kotlin implementations supply domain behavior themselves. The generic contract deliberately permits arbitrary `T`; it does not enforce C# constructor-time null rejection. Use Kotlin non-null storage or `Objects.requireNonNull` in a Java record's compact constructor. JSON null remains null at root, field and list-element positions; no wrapper is constructed. A concept whose `value()` is null writes JSON null (C# emits no scalar token). C# `Json/Globals.cs:52` `WhenWritingNull` is mapper configuration, not module behavior.
- **Unsigned types:** JVM `Byte` is signed (-128…127), unlike C# `byte` (0…255). The fixture value 42 is shared, but this is not an unsigned adapter. No unsigned widths are implemented. Jackson's default numeric parsing/coercion remains in force for ordinary scalar payloads.
- **Floating point:** Jackson emits whole Double/Float values with `.0`; System.Text.Json may emit integer-looking text. For example, 42.0 writes as `42.0` here and `42` in .NET. Exponents also differ (`1.0E100` versus `1E+100`). These oracle fixture rows are read-only; Kotlin tests separately pin emitted text. No global normalization is applied.
- **Decimal:** BigDecimal writes plain decimal notation, including for an input such as `1E+3`. Java precision/range and scale are not C# `decimal`'s bounded domain. Avoid treating exponent spelling or arbitrary BigDecimal magnitude as exact .NET numeric parity.
- **Strings:** Jackson emits non-ASCII characters such as `café` literally; System.Text.Json's default encoder may escape them. JSON values remain equivalent, but escaped bytes are not promised equal.
- **Dates and offsets:** LocalDate writes ISO `yyyy-MM-dd`. OffsetDateTime writes explicit seconds, 0–9 trimmed fractional digits and numeric offsets including `+00:00`. Reads parse ISO text directly, accept `Z` and preserve offsets regardless of Jackson's default time-zone adjustment. .NET has 100 ns precision and at most seven fraction digits; JVM nanoseconds are preserved rather than truncated. JVM temporal range is wider. No broader culture-sensitive .NET parsing or full temporal parity is promised.
- **TimeOnly:** LocalTime concepts always write `HH:mm:ss.fffffff`; raw LocalTime does so only with explicit `TemporalModule`. Finer nanoseconds truncate on write; reads accept ISO local times and retain JVM nanoseconds. This changes previously delegated LocalTime concept output; migrate stored wire expectations. Date/time parsing is ISO-only, not culture-sensitive .NET parsing.
- **Collections:** Scalar concept lists are arrays via normal Jackson delegation. Null list elements stay null in both directions; C# enumerable reads drop nulls and its scalar writer omits null tokens. Null collection stays JSON null. Non-array list input fails with DatabindException (C# returns an empty collection). This bounded list/array/set contract is not arbitrary collection conversion parity.
- **Enums:** Opt-in EnumModule writes JVM ordinals, not arbitrary C# numeric values. The leading UNDEFINED in the fixture aligns TWO with C# Two = 2. Reads accept defined ordinals, numeric strings, case-insensitive names, JsonProperty/JsonAlias and toString text (exact matches first); undefined numeric strings are rejected although C# Enum.TryParse accepts them. Flags, explicit values and non-int backing types are not supported. JsonValue/JsonFormat do not override this opt-in wire. Raw enum map keys remain Jackson names.
- **TimeSpan:** Opt-in TimeSpanModule writes Duration as canonical "c" strings and truncates toward zero to 100 ns, including negative sub-second values; truncated zero has no minus sign. Reads accept canonical two-digit hours/minutes/seconds with up to seven fractional digits, plus ISO-8601 for stored JVM payloads. No short day-only/hour-minute forms, culture-sensitive parsing, zero-on-failure, or C# TimeSpan range enforcement; extreme Duration absolute-value overflow can fail. Existing TemporalModule output is unchanged.
- **Map keys:** PLAIN remains the default: UUID, String and LocalDate use canonical underlying text; LocalTime uses fixed seven fractional digits; BigDecimal uses plain notation; OffsetDateTime uses the same explicit-seconds formatter as values. Primitive keys use invariant JVM parsing and Boolean keys accept exactly `true` or `false`. EMBEDDED_JSON on ConceptsModule instead serializes each concept through the same mapper's value handlers into compact JSON before writing the property name, like C# ComplexKeyDictionaryJsonConverterFactory. Reads try one complete non-null JSON value, then legacy text. Legacy text containing a JSON string literal is ambiguous and the decoded value wins; null, malformed or trailing JSON falls back to text. Jackson and STJ differ in outer quote escaping (`\"` versus `\u0022`), so dictionary fixtures compare trees, not bytes. Non-concept keys are unchanged.
- **Fallback:** Non-listed value/key types are delegated to Jackson. Successful delegation is not evidence of C# converter parity. Specialized collections, unsupported temporals, complex non-concept keys and derived types remain outside the bounded guarantee. Enum and Duration concepts use their raw opt-in modules through existing delegation.

## Boundary and ownership

Fundamentals owns shared domain concepts, correlation value identity, casing and the optional Jackson concept module. Arc.Kotlin retains its current `io.cratis.arc.concepts` / JSON implementations and does **not** depend on or re-export these artifacts yet. A later Arc extraction must switch dependencies explicitly and remove duplicated ownership in the same change. This repository does not own HTTP ingress policy, correlation propagation, Spring Boot wiring, Chronicle event modeling or generated clients. Do not introduce a hard Spring dependency into the core.

## Updating this map

Use exactly **Not implemented**, **Partial**, **Implemented**, or **Kotlin-specific**. For every surface, keep the pinned C# path, Kotlin API, executable test/fixture path and deviations/migration impact together. Every Not implemented row needs a real follow-up issue link. Missing behavior and deliberate differences are distinct; neither may be hidden behind a no-op or a broad claim of parity. Change this ledger with the implementation and its evidence. Compilation and round-trip tests alone are not exact cross-runtime wire evidence.
