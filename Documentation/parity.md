# Fundamentals Kotlin parity map

This ledger describes the Kotlin source at `8005a403a250ea72bf7a0b29a352de5cbe4aa445`, not a claim of whole-product parity or a published release. The two artifacts are `io.cratis:fundamentals` and `io.cratis:fundamentals-jackson`. Kotlin and Java share the same JVM API; Jackson integration is optional.

## Authority

The historical C# baseline for the fixtures is [Cratis Fundamentals](https://github.com/Cratis/Fundamentals/tree/f87af60265a2e59bd9b7435b0386ee06cb6d646a), pinned at **`f87af60265a2e59bd9b7435b0386ee06cb6d646a`**. Local C# `main` at `64945179db4b58cb5bfab7f9b85da585cc316556` has additional APIs and converter changes; the ledger does not establish parity with that newer revision. All C# paths in the ledger are relative to `Source/DotNET/Fundamentals` at the historical fixture pin unless explicitly prefixed `Fundamentals.Specs` (a sibling directory). Built-in Guid, DateOnly and DateTimeOffset JSON forms also depend on System.Text.Json. Hand-derived fixtures are not a live .NET oracle.

Kotlin implementation patterns and repository configuration are seeded from [Arc.Kotlin at 8a4a9be13b4e4a9bb5c20d238726c641fb4412a2](https://github.com/Cratis/Arc.Kotlin/tree/8a4a9be13b4e4a9bb5c20d238726c641fb4412a2). Casing fixtures originate in [Fundamentals.Go at c04690df426c5383b62dbf6c71bd799530d5bf0a](https://github.com/Cratis/Fundamentals.Go/tree/c04690df426c5383b62dbf6c71bd799530d5bf0a). Its older C# pin was checked against this authority: the casing implementation and specification are unchanged. Go-only invalid UTF-8 rows were removed; JVM UTF-16 preserves the original unpaired-surrogate case directly. See [casing provenance](../Source/Fundamentals/src/test/resources/strings/README.md) and [concept fixture provenance](../Source/Jackson/src/test/resources/golden/README.md).

## Concept conversion and exception mapping

Core has no Jackson dependency. Descriptors cache the existing record → public static `of` → public single-argument constructor order. Kotlin factories need `@JvmStatic`; named modules must open the package to reflection. `ConceptAs.valueTypeOf` retains its existing type-discovery behavior.

`ConceptFactoryConversionTest` pins the C# `ConceptFactory`, `ConceptMap` and `TypeConversion.cs` branches: identity, one-level concept unwrapping, canonical UUID strings and .NET's little-endian-first-fields 16-byte UUID representation; exact signed integer widths; numeric/string floating point and `BigDecimal`; boolean text; ISO date/time/offset text; and string targets (`BigDecimal.toPlainString`). `BigDecimal` identity retains scale. Collections and other targets have identity-only support, not general conversion parity. DateTime/LocalDateTime, TimeSpan/Duration and byte-array targets are not converted.

### Concept factory conversions

| Pinned `Types/TypeConversion.cs` branch | JVM result |
| --- | --- |
| 69–78: concept unwrap / already typed | Unwrap one level; preserve typed identity, including BigDecimal scale |
| 86–93: Guid | UUID text or 16 bytes in .NET field order; invalid input fails instead of empty Guid |
| 95–98, 209–211: string | `toString()`, except BigDecimal uses plain notation |

## Generated-value exception mapping

All generated-value errors map to `IllegalArgumentException`, except JVM non-null boundaries (`NullPointerException`). Factories are internal; there are no new public exception classes. The original pattern and parser reason are retained. Enum spellings and timestamp rendering use JVM forms.

| C# exception | JVM result |
| --- | --- |
| `InvalidValuePattern` | `IllegalArgumentException("Invalid value pattern '<pattern>': <reason>")`, including budget failures and invalid support indices |
| `InvalidIntegerRange` | `IllegalArgumentException` identifying both inclusive bounds |
| `InvalidNanoIdSize`, `InvalidNanoIdAlphabet`, `InvalidByteCount`, `InvalidTypeIdPrefix` | `IllegalArgumentException` preserving the respective bounds/alphabet/prefix reason |
| `UnknownChecksum` | `IllegalArgumentException("Checksum '<algorithm>' is not a supported checksum algorithm for this operation.")`; `NONE` is invalid for validation |
| `UnknownValueEncoding` | Undefined numeric enum values cannot be represented on the JVM; no runtime branch. Java null fails at the non-null boundary |
| `EmptyPatternSupport` | `IllegalArgumentException("Value pattern '<pattern>' has no values with an emittable check digit.")` |
| `PatternRequiresGenerationContext` | `IllegalArgumentException("Value pattern '<pattern>' requires a generation context for its UTC date segments.")` |
| `MissingGenerationTime` | `IllegalArgumentException("A generation context must contain the time the operation was received.")` |
| `GenerationTimeBeforeUnixEpoch` | `IllegalArgumentException` identifying the unsupported instant; applied to UUID v7, ULID and TypeID, not date patterns |
| `ArgumentNullException` | Java null arguments fail with `NullPointerException` at Kotlin non-null boundaries |
| JVM-only year range | `GenerationContext` construction rejects UTC years outside 1–9999 with `IllegalArgumentException`; C# cannot construct these values |

Patterns substitute one captured UTC date; the tenant does not affect built-in strategies. Checksum validation ignores printable nondigits in the payload but requires the exact numeric trailing suffix. Pattern membership is an internal shape check and does not imply arithmetic checksum validation. Both public validation entry points reject `Checksum.NONE`.

The vector tests enumerate 19 support, 25 invalid-pattern, 10 membership, 18 checksum and 24 validation rows. Screenplay binder assessments and range source parsing are deliberately outside this runtime API. UUID v7/ULID/TypeID timestamps are UTC Unix-epoch milliseconds; sub-millisecond precision is truncated. Captured date patterns can use pre-epoch dates other than the missing-time sentinel.

## Monads mapping

The six Result/Catch types port the public Monads contracts at `6ae7eb7d133afdb7adaf161ca185eaa189c7372b` (unchanged since the global `f87af60` pin and in local C# `main` at `64945179db4b58cb5bfab7f9b85da585cc316556`). `ResultTest` ports `Fundamentals.Specs/Monads/for_Result/{with_error_type,with_error_type_and_value}`; `CatchTest` ports `for_Catch/{without_value,with_value,with_error_type}`; `OptionEquivalentTest` ports `for_Option/when_{value,none_value}.cs`. Matching Java tests exercise the same consumer paths. This is not a port of OneOf itself.

| C# contract | JVM mapping / deliberate difference |
| --- | --- |
| Implicit conversions | Explicit `success`/`failed` factories or nested case constructors. |
| Explicit casts / `AsT0..2` | `tryGet*().orElseThrow()` or Kotlin smart casts; absent access throws `NoSuchElementException`, not `InvalidOperationException`. |
| `TryGet*(out x)` | `tryGet*(): Optional<…>`; Kotlin can use `getOrNull()`. |
| `Match` / `Switch` | `match` / `switchOn` on generic Result types and all Catch types, using Java functional interfaces; no-payload branches take `Supplier` / `Runnable` instead of `None`. |
| OneOf `Value` / `Index` / `IsTn` / `TryPickTn` | Not ported; use sealed cases, `isSuccess` and optional accessors. |
| Cross-type statics on `Result` / `Catch` | Not ported because of JVM erasure clashes; call the target type's own factory, e.g. `ResultWithValue.failed(error)`. |
| Null payloads | Rejected with NPE at Kotlin non-null boundaries; generic payloads have `Any` bounds. Use `ResultWithError` / `Catch` for no-value operations. |
| `Exception` | `java.lang.Exception`; JVM `Error`s are not modeled. |

## Wire and language differences

- **Concept values and null:** Java/Kotlin implementations supply domain behavior themselves. The generic contract deliberately permits arbitrary `T`; it does not enforce C# constructor-time null rejection. Use Kotlin non-null storage or `Objects.requireNonNull` in a Java record's compact constructor. JSON null remains null at root, field and list-element positions; no wrapper is constructed. A concept whose `value()` is null writes JSON null (C# emits no scalar token). C# `Json/Globals.cs:52` `WhenWritingNull` is mapper configuration, not module behavior.
- **Unsigned types:** JVM `Byte` is signed (-128…127), unlike C# `byte` (0…255). The fixture value 42 is shared, but this is not an unsigned adapter. No unsigned widths are implemented. Jackson's default numeric parsing/coercion remains in force for ordinary scalar payloads.
- **Floating point:** Jackson emits whole Double/Float values with `.0`; System.Text.Json may emit integer-looking text. For example, 42.0 writes as `42.0` here and `42` in .NET. Exponents also differ (`1.0E100` versus `1E+100`). These hand-derived fixture rows are read-only; Kotlin tests separately pin emitted text. No global normalization is applied.
- **Decimal:** BigDecimal writes plain decimal notation, including for an input such as `1E+3`. Java precision/range and scale are not C# `decimal`'s bounded domain. Avoid treating exponent spelling or arbitrary BigDecimal magnitude as exact .NET numeric parity.
- **Strings:** Jackson emits non-ASCII characters such as `café` literally; System.Text.Json's default encoder may escape them. JSON values remain equivalent, but escaped bytes are not promised equal.
- **Dates and offsets:** LocalDate writes ISO `yyyy-MM-dd`. OffsetDateTime writes explicit seconds, 0–9 trimmed fractional digits and numeric offsets including `+00:00`. Reads parse ISO text directly, accept `Z` and preserve offsets regardless of Jackson's default time-zone adjustment. .NET has 100 ns precision and at most seven fraction digits; JVM nanoseconds are preserved rather than truncated. JVM temporal range is wider. No broader culture-sensitive .NET parsing or full temporal parity is promised.
- **TimeOnly:** LocalTime concepts always write `HH:mm:ss.fffffff`; raw LocalTime does so only with explicit `TemporalModule`. Finer nanoseconds truncate on write; reads accept ISO local times and retain JVM nanoseconds. This changes previously delegated LocalTime concept output; migrate stored wire expectations. Date/time parsing is ISO-only, not culture-sensitive .NET parsing.
- **Collections:** Scalar concept lists are arrays via normal Jackson delegation. Null list elements stay null in both directions; C# enumerable reads drop nulls and its scalar writer omits null tokens. Null collection stays JSON null. Non-array list input fails with DatabindException (C# returns an empty collection). This bounded list/array/set contract is not arbitrary collection conversion parity.
- **Derived types:** Opt-in DerivedTypesModule uses explicit immutable registrations, never classpath discovery or Spring. Runtime `@DerivedType` ids must be nonblank and globally unique. The default Any/Object sentinel infers a single non-JDK interface (including inherited/transitive interfaces), otherwise the nearest non-JDK superclass; ambiguous interfaces need an explicit assignable targetType. Every non-JDK superclass is also indexed. Interfaces, abstract classes, enums, concepts and unannotated/inherited-only annotations are rejected as registrations. Repeated classes are idempotent. The id is independent of Chronicle event identity. Registered runtime classes emit `_derivedTypeId` last, including concrete/Object declarations; use runtime writes rather than explicitly static interface writers. Reads accept the id in any position, remove it before ordinary bean delegation, and dispatch nested properties, lists, arrays, maps and recursive families. Missing/differently-cased ids return null (C# parity); unknown, null and non-string ids fail. An annotated unregistered member of a registered family fails on write; unannotated implementations remain Jackson-owned. Jackson naming, creators, annotations, null inclusion and custom body serializers are not a System.Text.Json clone. Combine registrations into one registry per mapper: a second module replaces rather than merges; EMPTY is a no-op. The fixture is hand-derived from the pinned source/specifications, not a live .NET oracle. Native Jackson type ids/default typing are outside this contract. Relative to the pinned C# source, concrete/Object declarations also write ids (D3), missing ids return null unchanged (D4), superclass-only primary targets are a JVM superset (D5), and bodies honor Jackson rather than C# reflection naming/inclusion (D6). Generic specialization is best effort: `constructSpecializedType` failures become mapping errors, but fixed generic arguments with no bindable subtype parameters are not additionally validated.
- **Enums:** Opt-in EnumModule writes JVM ordinals, not arbitrary C# numeric values. The leading UNDEFINED in the fixture aligns TWO with C# Two = 2. Reads accept defined ordinals, numeric strings, case-insensitive names, JsonProperty/JsonAlias and toString text (exact matches first); undefined numeric strings are rejected although C# Enum.TryParse accepts them. Flags, explicit values and non-int backing types are not supported. JsonValue/JsonFormat do not override this opt-in wire. Raw enum map keys remain Jackson names. No enum-value or flags contract is defined here. C# expresses explicit values and `[Flags]` in the language and in `System.FlagsAttribute`, not in Fundamentals. Do not assume a consuming application's enum codec has the same contract.
- **TimeSpan:** Opt-in TimeSpanModule writes Duration as canonical "c" strings and truncates toward zero to 100 ns, including negative sub-second values; truncated zero has no minus sign. Reads accept canonical two-digit hours/minutes/seconds with up to seven fractional digits, plus ISO-8601 for stored JVM payloads. No short day-only/hour-minute forms, culture-sensitive parsing, zero-on-failure, or C# TimeSpan range enforcement; extreme Duration absolute-value overflow can fail. Existing TemporalModule output is unchanged.
- **Map keys:** PLAIN remains the default: UUID, String and LocalDate use canonical underlying text; LocalTime uses fixed seven fractional digits; BigDecimal uses plain notation; OffsetDateTime uses the same explicit-seconds formatter as values. Primitive keys use invariant JVM parsing and Boolean keys accept exactly `true` or `false`. EMBEDDED_JSON on ConceptsModule instead serializes each concept through the same mapper's value handlers into compact JSON before writing the property name, like C# ComplexKeyDictionaryJsonConverterFactory. Reads try one complete non-null JSON value, then legacy text. Legacy text containing a JSON string literal is ambiguous and the decoded value wins; null, malformed or trailing JSON falls back to text. Jackson and STJ differ in outer quote escaping (`\"` versus `\u0022`), so dictionary fixtures compare trees, not bytes. Non-concept keys are unchanged.
- **Fallback:** Non-listed concept values and key reads delegate to Jackson; plain concept-key writes fall back to `toString()`. Successful delegation is not evidence of C# converter parity. Specialized collections, unsupported temporals, complex non-concept keys and polymorphism beyond the explicit derived-type contract remain outside the documented compatibility scope. Enum and Duration concepts use their raw opt-in modules through existing delegation.

C# derived-type errors `AmbiguousDerivedTypeIdentifiers`, `AmbiguousTargetTypeForDerivedType`,
`MissingTargetTypeForDerivedType`, `MissingDerivedTypeForTargetType` and
`TargetTypeMismatchForDerivedType` map to JVM `IllegalArgumentException` at registry construction
or lookup. Malformed/unknown JSON ids and specialization failures map to Jackson `DatabindException`
(with the underlying lookup/specialization cause retained).

## Boundary and ownership

For consumer construction and mapper setup, follow the [README registration guidance](../README.md#jackson-registration-and-construction). The ownership and compatibility decisions below are ledger context, not an additional setup sequence.

Fundamentals owns shared domain concepts, correlation value identity, casing, explicit derived-type registration and the optional Jackson modules. This source does not establish which Fundamentals APIs or Jackson modules Arc.Kotlin consumes; integration is tracked separately in Cratis/Arc.Kotlin#301. Check the consuming application's mapper configuration before adding modules, especially if it already handles concepts, enums or `_derivedTypeId`. Matching annotations or discriminator names do not establish compatible serialization behavior. This repository does not own HTTP ingress policy, correlation propagation, Spring Boot wiring, Chronicle event modeling or generated clients. Core has no hard Spring dependency.
